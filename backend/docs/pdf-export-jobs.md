# Version-linked PDF exports

Each export belongs to one saved report version, its snapshot SHA-256, and its
template version. `POST /api/v1/reports/{report_id}/versions/{version_id}/pdf-exports`
accepts `{"template_version":"report-v1"}` with an `Idempotency-Key`. The service
commits a queued attempt in PostgreSQL before best-effort Celery publication.
`POST .../{export_id}/retry` accepts the last `expected_attempt_count` and the
64-character `input_identity`; a retry creates a new attempt on the same export.
The list and detail routes expose persisted state. The existing download route
streams only a completed, owner-authorized and checksum-verified asset.

Run a worker with `celery -A app.jobs.worker_entry.celery_app worker --loglevel=INFO`
from `backend/` after configuring PostgreSQL, Redis, and S3-compatible storage.
Install Playwright Chromium with `python -m playwright install chromium`, or set
`PDF_BROWSER_EXECUTABLE_PATH` to an absolute compatible browser path. The PDF
worker needs the same storage credentials and bucket as the API. Generated keys
include the attempt ordinal; private unbound objects from an interrupted upload
are never downloadable and should be removed by a bounded bucket lifecycle rule.

`PDF_RENDER_TIMEOUT_SECONDS` bounds browser rendering.
`PDF_TASK_TIME_LIMIT_SECONDS` bounds the entire Celery task and must exceed the
render timeout plus `OBJECT_STORAGE_TIMEOUT_SECONDS` and five seconds.
`PDF_STALE_RUNNING_SECONDS` must exceed the task limit. Defaults are 30, 180,
and 360 seconds respectively. `GENERATED_PDF_MAX_BYTES` bounds generated bytes.
Run `python -m app.jobs.reconcile` periodically to republish up to 100 queued
attempts and fail up to 100 stale running attempts. PostgreSQL remains the
source of job state if broker publication fails.
